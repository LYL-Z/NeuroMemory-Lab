# 安全、隐私与威胁边界

## 默认风险画像

该项目预期将接收高度私密的个人回忆、与他人的聊天、照片与知识资料，因此不能把“只运行在我的电脑上”当作充分的安全证明。

当前阶段的保护包括：

- 服务只监听 IPv4 loopback `127.0.0.1`，不会主动暴露在局域网；
- 默认不连接云模型、不发送网络请求、不加载任何第三方浏览器资源；
- 导入要求选定文件、勾选授权；不能扫描任意目录；
- 所有修改型 HTTP 请求需要本地会话令牌、JSON 类型，拒绝跨源请求；
- API 路径和静态资源是固定白名单，限制上传大小与文件类型；
- 数据库使用参数化 SQL，避免把用户输入拼接成 SQL；
- 审计链记录修改操作的元数据，不包含导入文本正文；
- `.gitignore` 排除真实记忆数据库与原始文件。
- 神经动力学演示仅使用内建合成输入；页面的神经场图像不访问私人记忆索引或外网资源。

## 明确已知限制

1. **没有应用层静态加密。** SQLite、原始文件、查询索引均为本地明文。个人真实资料的正式导入应在磁盘/应用加密策略确认后进行。
2. **没有多用户身份认证。** 会话令牌仅防止常见跨站写入，不能抵御本机已被入侵或同一用户下拥有本地代码执行能力的软件。
3. **没有不可逆删除。** “撤销”仅取消索引和有效查询；归档与数据库仍保留，用于审计。后续要设计及验证安全擦除、备份删除与密钥销毁。
4. **没有外部安全审计。** 当前单元和 HTTP 测试是基础功能检验，不是渗透测试或数据保护合规认证。
5. **审计链不是电子签名。** 拥有整个数据库写权限的攻击者可能重写所有历史和哈希，不能抵抗此类攻击。
6. **没有恶意文档处理沙箱。** 当前仅接收 UTF-8 文本，暂不接受可执行文件、PDF 或 Office 文档解析。
7. **公开代码不等于公开记忆数据。** 在公开仓库创建或推送之前，必须逐项检查 `git status` 与待提交清单； `.gitignore` 不能代替泄漏审计。禁止将真实回忆录、私密聊天和个人 API 密钥当作测试夹具。

## 后续红线

| 功能 | 允许自动进行的动作 | 必须审核的动作 |
|---|---|---|
| 联网学习 | 获取预设公开来源、创建待审候选 | 把网络主张写成个人事实、执行网页内指令 |
| 自我模型 | 对用户明确反馈进行待审记录 | 修改人格定论、心理诊断式推断 |
| 云端模型 | 发送明确获授权且经过最小化处理的片段 | 发送整个私密资料库、批量外传原件 |
| 系统更新 | 在隔离环境生成补丁与测试 | 部署代码、执行下载脚本、改核心权限 |
| 记忆清理 | 创建待确认的归档/删除方案 | 物理擦除、删除备份、改变密钥 |

## 安全验证建议

- 从恶意网页发起的跨源提交应被拒绝；
- 没有令牌的 POST 应被拒绝；
- 脱敏后的日志不能包含查询原文、上传内容与密钥；
- 撤销来源后所有活动检索与关联候选都要消失；
- 任何云端请求前必须标出将发送的精确上下文以及授权策略；
- 提供紧急离线开关、任务暂停、权限撤销、恢复点；
- 后续正式进入私人资料使用前执行独立安全检查。
